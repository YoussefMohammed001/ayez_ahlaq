# عايز أحلق (Ayez Ahlaq) — Project Brief for the Developer

هذا الملف بديل عن إرسال المحادثة كاملة — ملخص منظم لكل حاجة اتقالت واتقررت، عشان تقدر تبدأ الشغل من غير ما تحتاج ترجع لأي حد يسأل.

## الفكرة الأصلية

تطبيق حجز حلاقين بالعربي. المستخدم يفتح التطبيق، يختار الصالون (بترشيح حسب أقرب موقع، أو لو دخل من رابط دعوة حلاق بيتحط في مفضلته أوتوماتيك)، يختار الحلاق جوه الصالون، يختار نوع الخدمة، يختار شكل القصة بالاسم، يختار المعاد، ويشوف حالة الطابور لحظيًا (كام واحد قدامه). الفكرة اتوسعت بعد كده لتلات تطبيقات منفصلة بيتكلموا مع بعض من خلال نفس القصة التجريبية.

## التطبيقات التلاتة

| التطبيق | الفولدر | المستخدم |
|---|---|---|
| **العميل** | `ayez_ahlaq_customer/` | أي حد عايز يحجز حلاقة أو يشتري منتجات |
| **الحلاق** | `ayez_ahlaq_barber/` | الحلاق نفسه — طابور، جدول، أرباح، فريق العمل |
| **التاجر** | `ayez_ahlaq_merchant/` | تاجر جملة بيبيع مستلزمات حلاقة **للحلاقين بس**، مش لعميل عادي خالص |

كل تطبيق مشروع Flutter مستقل بالكامل (`pubspec.yaml` + `lib/` خاص بيه)، لكن التلاتة بيشتركوا في نفس هوية التصميم (كحلي + ذهبي، خط Cairo/Reem Kufi، RTL بالكامل) ونفس بيانات الديمو (مثلاً محمد سعيد وحجزه مع مختار توفيق الساعة ١٢:٣٠ ظاهرين في تطبيق العميل والحلاق مع بعض) عشان العرض يحكي قصة واحدة متماسكة.

## البروتوتايبات التفاعلية (للعرض السريع بدون تشغيل الكود)

فولدر `prototypes/` فيه ٣ ملفات HTML مستقلة (تفتح بأي متصفح مباشرة، من غير سيرفر ولا تنصيب):
- `ayez-ahlaq-customer.html` — تجربة العميل كاملة
- `ayez-ahlaq-barber.html` — لوحة الحلاق كاملة
- `ayez-ahlaq-merchant.html` — تطبيق التاجر

دول بروتوتايبات JavaScript خفيفة لغرض المعاينة والموافقة على الفلو بس — **مش الكود الحقيقي**. الكود الحقيقي اللي هيتسلم للتطوير هو مشاريع Flutter التلاتة.

## مواصفات كل تطبيق بالتفصيل

### ١. تطبيق العميل (`ayez_ahlaq_customer`)

الفلو الكامل: تسجيل دخول برقم موبايل (أو دخول كزائر) → OTP → الرئيسية (ترشيح بالموقع + قسم مفضلة) → اختيار الصالون → اختيار الحلاق → اختيار نوع الخدمة → **اختيار شكل القصة بالاسم** (مولت، فيد أمريكي، أندركت، بومبادور، باز كت، كريو كت... كل واحد بمربع صغير ولون مختلف، وبيغيّر السعر) → اختيار المعاد (مع حالة الطابور اللحظية وعدد الحاجزين) → ملخص الحجز والدفع → تأكيد.

بالإضافة لكده:
- **المفضلة عبر رابط الدعوة**: لو المستخدم دخل من لينك حلاق، الحلاق ده بيتثبّت في مفضلته تلقائيًا مع شارة "من رابط الدعوة".
- **متجر عام (تاب رئيسي)**: منتجات عناية وأدوات حلاقة، سلة، إتمام طلب، وتتبع الطلبات ("طلباتي").
- **منتجات الحلاقين الشخصية**: في صفحة أي صالون، تحت قائمة الحلاقين، قسم "منتجات الحلاقين هنا" — منتجات بيبيعها الحلاق بنفسه (مختلفة عن كتالوج المتجر العام اللي بييجي من التجار).
- **حجوزاتي**: الحجز الحالي وحالته في الطابور، والحجوزات السابقة مع تقييم الخدمة.

### ٢. لوحة الحلاق (`ayez_ahlaq_barber`)

التابات الرئيسية: **لوحتي** (داشبورد باليوم)، **الطابور**، **المتجر** (نفس تجربة شراء المستلزمات بتاعة العميل، لكن هنا التاجر هو المورّد)، **الفريق** (ترتيب كل حلاقين الصالون حسب عدد العملاء الشهر ده والتقييم)، **أرباحي**، **حسابي**.

جوه "حسابي → الإدارة":
- **جدول المواعيد** (نُقل من تاب رئيسي لهنا).
- **منتجاتي**: الحلاق يرفع منتجاته الشخصية (اسم، فئة، سعر، وصف) وتظهر تلقائيًا لعملاء تطبيق العميل في صفحة صالونه.
- **خدماتي وأسعاري**، **تقييمات العملاء**، **مشاركة رابطي** (رابط الدعوة اللي بيوصل العميل للمفضلة).

من تاب "الطابور": زرار **"عميل من الشارع"** — تسجيل حجز يدوي لعميل جه شخصيًا من غير حجز أونلاين (اسم، أنهي حلاق من الفريق، الخدمة، المعاد، وحالته دلوقتي)، وبيتحدث في نفس الجدول اللي بيشوفه العملاء أونلاين.

**جاهز للديسكتوب**: نفس كود الفلاتر ده مبني بحيث يشتغل Windows/macOS/Linux desktop من غير أي تعديل (شايف قسم "Desktop build" تحت).

### ٣. تطبيق التاجر (`ayez_ahlaq_merchant`)

تطبيق B2B مقفول بالكامل — مفيش أي واجهة بيع لعميل عادي فيه خالص:
- **لوحتي**: طلبات معلقة، إيرادات الشهر، المنتج الأكثر مبيعًا، أحدث الطلبات.
- **منتجاتي**: كتالوج الجملة (اسم، فئة، سعر الوحدة، **الحد الأدنى للطلب**، **الكمية بالمخزن**) — بيبان بس جوه "المتجر" في تطبيق الحلاقين.
- **الطلبات**: طلبات واردة من الصالونات (اسم الصالون + الحلاق المسؤول)، بحالة شحن بتتحرك: جاري التجهيز → في الطريق → اتسلم.
- **حسابي**: بيانات النشاط التجاري.

## نظام التصميم (مشترك بين التلاتة)

- **الألوان**: خلفية كحلي دافئ (`#1C1916` وما حواليها) + لمسة ذهبي/نحاسي (`#C6982F`) كلون أساسي.
- **الخطوط**: Reem Kufi للعناوين، Cairo لباقي النصوص — الاتنين بيدعموا العربي كويس، عبر حزمة `google_fonts` (تحميل وقت التشغيل، مفيش خطوط لازم تتحمّل يدويًا).
- **الاتجاه**: RTL بالكامل، متفروض برمجيًا في `main.dart` (مفيش `flutter_localizations` لسه — يتضاف لو عايزين لغة إنجليزي كمان).
- **State management**: `provider` — كل تطبيق عنده كلاس واحد (`AppState` / `BarberState` / `MerchantState`) بيمسك الحالة كلها، والشاشات بتقرا منه بس، مش من بيانات الديمو مباشرة.

## هيكل الكود (نفس الشكل في التطبيقات التلاتة)

```
lib/
  main.dart          نقطة الدخول، الثيم، وربط Provider
  theme/              الألوان والخطوط
  models/             كلاسات بيانات بسيطة
  data/mock_data.dart كل بيانات الديمو — مكان واحد لاستبدالها بـ API حقيقي
  state/              الكلاس الوحيد اللي بيمسك حالة التطبيق
  widgets/            مكونات مشتركة (أزرار، كروت، badges...)
  screens/            شاشة في كل ملف
```

## طريقة التشغيل

```bash
cd ayez_ahlaq_customer   # أو ayez_ahlaq_barber / ayez_ahlaq_merchant
flutter create . --platforms=android,ios
flutter pub get
flutter run
```

`flutter create .` بس بيضيف فولدرات android/ios الناقصة، مبيلمسش الكود.

### تشغيل لوحة الحلاق كديسكتوب (Windows)

```bash
cd ayez_ahlaq_barber
flutter create . --platforms=windows
flutter pub get
flutter build windows
```

الملف التنفيذي هيطلع في `build\windows\x64\runner\Release\ayez_ahlaq_barber.exe` — لازم تتنقل مع كل ملفات `.dll` جنبها لو هتتبعت لحد تاني.

**ملحوظة**: الأوامر دي محتاجة Flutter SDK + Visual Studio (Desktop development with C++ workload) متثبتين على الجهاز اللي هيعمل البيلد.

## أماكن ربط باك إند حقيقي

1. `lib/data/mock_data.dart` في كل تطبيق — استبدل القوائم الثابتة بـ API calls بترجع نفس شكل الـ models.
2. `lib/state/*.dart` — الميثودز زي `confirmBooking`, `addToCart`, `startService`, `addWalkIn`, `advanceOrderStatus` دلوقتي بتعدّل قوائم في الميموري بس؛ استبدل جسمها بـ API calls ومفيش حاجة في `screens/` هتحتاج تتغيّر.

## حاجات مهم الديفلوبر يعرفها

- التلاتة تطبيقات **مفيهمش باك إند حقيقي** — كل واحد بياناته منفصلة في الميموري. عشان كده بعض البيانات (زي منتجات محمد سعيد الشخصية) اتكررت يدويًا في أكتر من تطبيق عشان الديمو يحكي قصة متماسكة — لما يتوصل API حقيقي المشكلة دي بتتحل تلقائيًا.
- الكود اتعمل مراجعة يدوية دقيقة (توازن الأقواس، الـ imports، تسمية الكلاسات) لكن معملناش `flutter analyze` فعليًا لعدم توفر Flutter SDK في بيئة الكتابة — لو ظهرت أي ملاحظة بسيطة بعد أول build، ده متوقع وطبيعي.
- مفيش نظام تسجيل دخول/صلاحيات حقيقي بين التطبيقات التلاتة — كل واحد بيفترض إن المستخدم بتاعه (عميل/حلاق/تاجر) معروف مسبقًا.
